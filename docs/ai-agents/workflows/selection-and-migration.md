# 工具选择与迁移

目标：从实际约束选工具，不追逐无依据的排名；迁移时保留项目文件和必要状态。可从[栏目首页](../index.md)进入各篇。

## 先按约束筛选

先确认平台与 shell、模型服务/账号、是否接受 API 按量费用、是否需离线或自托管、扩展和团队规则要求。工具列表见 [Codex](../harnesses/codex.md)、[Claude Code](../harnesses/claude-code.md)、[OpenCode](../harnesses/opencode.md)、[Pi](../harnesses/pi.md)、[oh-my-pi](../harnesses/oh-my-pi.md)、[DSH](../harnesses/dsh.md)、[Hermes](../harnesses/hermes.md)、[Kimi Code](../harnesses/kimi-code.md)。

## 对照维度

| 维度 | 需要核实的问题 |
| --- | --- |
| 平台 | 是否官方支持当前系统、shell、架构？ |
| 接入 | 官方账号、API Key、自托管端点分别怎样授权？ |
| 工作方式 | 交互 TUI、桌面/Web UI 或非交互 CLI？ |
| 配置 | 项目规则、会话与扩展能否按需复用？ |
| 权限 | 文件访问和 shell 执行如何确认？ |
| 生命周期 | 版本、数据导出、迁移和卸载是否明确？ |

不要根据单一基准测试或社区转帖推断个人项目中的效果。先用 P07 小任务实测并比较文件差异。

## 从一款工具迁移到另一款

先备份项目工作区和配置；记录未完成任务、模型提供商、项目规则和实际环境。安装新工具并重新认证，在干净的新会话完成只读任务，再执行小范围写任务。检查新旧工具配置格式，不直接复制 token、会话数据库或插件数据。
