# Codex 写作提示词

## 使用方法

完整任务用于撰写全部正文并接入站点；单章任务用于按页分批完成。执行前替换尖括号占位符，不把占位文字发布到正文。

这份文件的存在不自动触发写作；用户明确发起完整任务或单章任务后，才按对应范围执行。

## 完整写作任务

```text
请按照 prompts/ai-agents/ 下的资料包，为当前 Zensical 博客完成 AI Agents 栏目的 27 个中文页面，并接入导航。

先读当前有效的 AGENTS.md，检查 git status，保留用户已有改动。再依次读取本目录的 README、实施计划、详细大纲、来源清单、写作规范和验收清单。页面 ID、路径和导航层级以资料包为准。

目标读者从入门到进阶，Windows 日常操作以 Git Bash 为主，兼顾 WSL 2、macOS 和 Ubuntu LTS。仓库命令执行仅用 Git Bash；教程中需要展示的其他终端安装步骤明确标注，不在本机自动运行。

请依次完成：
1. 阅读并核验各页所需官方资料，记录目标版本、实际读取页面和核验日期。
2. 编写 P02–P07 基础页面。P03 合并 Git Bash 与 PowerShell 7；Windows 先安装 Scoop，再用它安装并介绍 `rg` 与 `fd`，将 PATH 单独成节并解释 Windows 用户/系统变量、进程继承和 Git Bash `$PATH` 转换差异；P04 Ubuntu 基础工具加入 `fd-find` 和检查后创建用户级 `ln -s` 的 `fd` 命令；P05 在 macOS/Linux 的 Git 与 ripgrep 安装中增加 fd，并区分 Homebrew `fd` 与 Ubuntu/Debian `fd-find`；P03–P05 按平台讲 nvm；P06 讲 uv 优先与 Anaconda3/Conda；P07 给出 agent-lab 完整初始文件与任务。
3. 按 P08–P16 顺序完成九篇 Harness 教程，遵守共同章节合同并展开专属内容；P15 WorkBuddy 按桌面工作台介绍，P16 Hermes 介绍学习闭环与消息网关。
4. 按 P17–P24 顺序完成配套工具（CC Switch、模型 API 协议与 DeepSeek 接入、Herdr）、日常工作流、项目指令与 AGENTS.md、扩展、选择迁移、自动化。Herdr 先讲基础终端，多 Agent 实践要求先读 P24 的协作原则。然后完成 P25–P27 参考页面，最后完善 P01 栏目首页、交叉链接、比较表和速查。
5. 全部正文完成后，在 zensical.toml 中将 AI Agents 插入 Home 与 Miscellaneous 之间；保留当时已有的其他导航。在 docs/index.md 添加简短入口。
6. 按验收清单审校，使用现有可用环境执行文档构建，并记录实际检查结果。

每页都要有真实内容、明确的学习结果、可执行步骤、预期结果和排障入口。九篇工具教程必须从安装与认证讲到第一次任务、日常使用和维护，不能用官网链接或待办代替内容。

具体要求：
- 公共概念集中说明，工具篇链接公共页，同时保留本工具的实际操作。
- Windows 按需要分别使用 Git Bash 与 PowerShell 7 标签，WSL/macOS/Linux 使用统一平台标签及四空格缩进；区分启动终端和 Agent 内部执行 shell。
- Windows 文档先写 Scoop 安装，再写 Scoop 安装 `ripgrep`/`fd` 与用途、验证；PATH 独立说明 Windows 系统/用户/进程范围及 Git Bash 继承转换。WSL 用 Ubuntu `fd-find`/`fdfind`，说明安全的 `ln -s`；macOS 与 Linux 均提供 Git、rg、fd 的安装和来源验证。
- 内容按学习逻辑合并和排序：PowerShell 7 与 Git Bash 同页，AGENTS.md 撰写与项目指令/上下文同页；不能将后加专题机械放到末尾或重复建页。
- nvm-windows 与 nvm-sh 分开讲安装、初始化、选择适用 Node LTS、验证、切换和全局包差异。解释 nvm 管理 Node.js，npm 随当前 Node 提供，不声称独立管理任意 npm 版本。
- Python 环境优先 uv，完整覆盖安装、解释器、项目 .venv、依赖锁定、运行、工具隔离和复现；再独立讲 Anaconda3 安装、Conda 环境激活、包管理和导出，说明与 uv、Windows/WSL 的边界。
- AGENTS.md 给出 agent-lab 与 Zensical 两套完整模板、根/子目录规则和验证方法；不覆盖真实项目规则，不假定九款工具加载规则相同。
- CC Switch 按受支持客户端编写安装、配置切换、验证及备份恢复；Herdr 先讲终端布局，再讲状态和协作，所有控制示例以受管理环境与真实 ID 为前提。
- 根据当前官方资料确认项目身份、版本、安装包、平台支持、配置、命令和认证方式。
- P22 通用介绍并比较 prompts、Skills、MCP、RAG、memory、plugins 和 hooks 的职责、适用时机、边界与组合方式；Zotero 只用 `54yyyu/zotero-mcp` 展示 MCP server 和 `zotero-cli` Skill 两种接入路线。不要用 Zotero 项目替代通用解释，也不要把该项目的功能推及所有工具；核验当前官方资料与权限边界。
- P15 WorkBuddy 以桌面流程为主，核实每个平台安装入口、登录方式、工作空间和默认权限；对项目指令、会话保存及扩展不作未经官方确认的承诺。桌面交互与 CLI 分开描述。
- P16 Hermes 介绍技能创建与改进、分层跨会话记忆、并行委派、Cron、代码批处理、原生工具与 MCP，以及企业微信网关配置和访问控制；工具数量以当前官方资料为准。
- Codex 使用官方 OpenAI 文档及当前可用的 OpenAI Docs 技能；其他工具使用各自官方来源。
- Pi、OpenCode、Kimi 的项目或版本迁移重新核验；DSH 采用官方当前界面，不虚构终端聊天模式；Hermes 的待核验能力查证后再写。
- 不支持或未确认的能力明确说明，不把另一个工具的功能、命令或权限机制移植过来。
- 不编造输出或测试结果，区分官方文档核验与本机实测。未实测平台保留记录。
- 使用相对 Markdown 链接与现有扩展；不增加主题依赖、插件或 CI 配置。
- 每完成一页就更新 prompts/ai-agents/03-official-sources.md 和 06-acceptance-checklist.md。

边界：不在本机安装 Harness、PowerShell、nvm、uv、Anaconda3、CC Switch 或 Herdr；不切换实际 Node 版本、改写真实提供商配置、创建或控制 Herdr pane；不调用模型、不启动付费服务、不创建或升级环境、不自动提交、推送或部署。安装与环境练习是给读者的教程内容，资料查询与 Markdown 编辑可继续。

已授权的验证是静态审校、现有环境下的 Zensical 构建和可用条件下的页面预览。不要为本次文档任务安装依赖或让 uv 隐式创建环境。构建环境不足时记录具体原因；完成其余可完成的内容，不把未执行项写成通过。

工具文档不可达时，先尝试官方 README、文档目录、发行说明。仍有关键缺口时，不发布未经核实的命令；在进度表中记录问题，并继续独立页面。无法完成所有页面时，最终明确列出剩余项，保持整体任务未完成，不能把有占位内容的栏目接入导航。

最后报告：完成页面、修改文件、来源核验范围、构建与呈现检查结果、尚未验证的平台及未解决问题。不要只输出建议或下一步计划，实际完成当前授权范围内的工作。
```

## 单章任务

```text
请按 prompts/ai-agents/ 资料包撰写页面 <PAGE_ID，例如 P08>。

先读 AGENTS.md 和 git status，再读资料包入口、实施计划、详细大纲中对应页面、官方来源、写作规范及验收清单。页面路径、先修关系、二三级标题和练习目标以大纲为准。

先读取该章对应官方资料，核对版本、安装包、平台、命令、配置和认证；然后直接创建或完善目标 Markdown。适用时遵守工具篇统一章节合同，并展开专属大纲。不得只写通用介绍或复制另一工具的命令。

采用 Windows Git Bash 主线，适用时提供独立的 PowerShell 7 标签，并区分 WSL/macOS/Linux；遵守四空格缩进与相对 .md 链接。按最终页面清单处理合并章节，不另外创建 PowerShell 或 AGENTS.md 重复页。nvm 与 Python、CC Switch、Herdr 的范围遵守大纲；所有示例标明执行环境和预期结果，未经运行的输出不能写成实测。

如果所需先修页面尚未编写，记录依赖并引用大纲规定的目标路径；不得用占位页伪装先修内容已经完成。不要为了本次单章写作扩展到其他正文、首页或站点导航。跨页链接允许暂时指向大纲中尚未生成的页面，但必须记录为“计划内待生成”，最终发布前必须全部补齐。

编辑只用 apply_patch，终端只用 Git Bash。不得安装 Harness 或配套软件、切换 Node 版本、调用模型、控制 Herdr、安装依赖、创建环境或提交推送。本任务只要求文档来源与静态审校；除非用户另行要求，不运行站点构建。

完成后更新来源核验记录和该页进度，报告完成内容、来源核验范围、未验证平台和待生成链接。若关键事实未确认，准确标记未完成并说明缺口。
```

## 续写任务

```text
继续 AI Agents 栏目写作，沿用此前已授权的任务范围。

先读 AGENTS.md、git status、prompts/ai-agents/README.md、06-acceptance-checklist.md 和 03-official-sources.md，再读取下一页的大纲与写作规范。

区分“已计划”“草稿”“已核验”“已审校”和“已发布”；不要重写已完成页面或把前次未验证项自动标为通过。按实施计划继续下一项，每页完成后更新记录。

如果此前是完整写作任务，继续直到全部正文和最终站点接入完成；如果此前是单章任务，只续写该章。若上下文中无法确定此前授权范围，先做只读检查并确认目标，不默认扩展到全站。

保持 Windows Git Bash 主线、官方资料核验、四空格缩进与跨平台标签约定。不安装工具或依赖、不调用付费服务、不自动提交推送。最终报告实际进展、未完成项和检查结果。
```

## 审校任务

```text
请审校 AI Agents 栏目，范围为 <PAGE_ID / 页面列表 / 全部栏目>。

先读取 AGENTS.md、资料包的大纲、来源、规范和验收清单，并检查现有改动。重新核验涉及安装、认证、平台、配置、权限、快捷键和版本迁移的官方来源。

检查页面是否达到各自验收条件：有完整操作流程、步骤和预期结果；Windows 与 WSL 不混用；PowerShell 7、nvm、uv/Conda、AGENTS.md、CC Switch 与 Herdr 已按学习顺序合并或安排，27 页编号和导航一致，Hermes 排在第九款 Harness；环境和工具功能有依据；代码块适合复制；无凭据与本机私有路径；相对链接、平台标签、四空格缩进正确。

直接修正文档范围内有证据支持的问题，保留用户无关改动。不能证实的功能和命令记录为缺口，不用猜测补齐。比较表和命令速查必须与已核验正文一致。

默认只做资料核验与静态审校。用户要求全栏目发布验收时，才按验收清单在现有环境执行构建和页面呈现检查；不能安装依赖、创建环境或运行真实模型任务。

更新相关来源与进度记录，报告已修复的问题、检查结果和剩余缺口，不把未完成的验证写成通过。不自动提交、推送或部署。
```
