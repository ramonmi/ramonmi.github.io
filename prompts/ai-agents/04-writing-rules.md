# 写作与 Zensical 规范

## 文风和内容深度

使用简体中文，工具名和代码保持官方写法。每节先说明读者要达到什么结果，再给操作和验证方法。新术语首次出现时解释，公共概念链接入门页；避免连续堆砌产品功能名称。

每个关键步骤按“在哪里操作 → 做什么 → 预期看到什么 → 没看到时查什么”展开。安装、认证、首次任务必须有可操作步骤，不能只列官网链接。完成基础闭环后再介绍可选进阶。

不设机械字数门槛。工具篇须满足 [统一章节合同](02-content-outline.md#工具篇统一章节合同)，不能用一句“参考官方文档”替代正文。比较按读者任务、平台与配置成本组织，不给缺乏证据的能力排名。

## 终端与平台约定

- Windows 环境页统一讲 Git Bash 与 PowerShell 7，日常操作以 Git Bash 为主。区分 Windows Terminal、Git Bash、PowerShell 7、Windows PowerShell 5.1 与 WSL，并验证 pwsh 的真实版本。
- 本仓库的自动化命令执行只允许 Git Bash；教程展示其他终端的官方安装步骤，不代表作者获得了在本机运行这些步骤的授权。
- 官方安装使用 PowerShell 时，明确适用 7 还是 5.1；提供独立的 PowerShell 7 代码块，并解释随后回到哪个终端。不得把 PowerShell 命令改写成未经验证的 Bash 命令，不以安装新 shell 替代配置 Agent 内部 shell。
- 每款工具明确“启动终端”和“Agent 内部执行 shell”。Git Bash 启动不代表 Agent 必然用 Bash 执行命令。
- WSL 中使用 Linux 安装、Linux 运行时和 Linux 凭据目录；不默认与 Windows 原生共享。区分 `C:/...`、`/c/...`、`/mnt/c/...`。
- macOS 与 Linux 使用 Bash/Zsh 兼容示例并注明差异。Linux 主例为 Ubuntu LTS，其他发行版指向官方说明。
- 路径参数始终加引号；用 `"${HOME}/..."`，不使用裸 `~`。进入项目目录前说明路径占位符。
- Bash 环境变量写法只用于 Bash 代码块；PowerShell 与配置文件分别使用真实语法。区分临时变量、持久配置和凭据存储。
- 不默认需要管理员权限，不推荐全局关闭安全检查或随意使用 `sudo` 修复安装。
- 基础教程按需安装运行时，不要求为了使用一个工具预先安装全部语言环境。精确版本要求来自官方资料。

## Node.js/npm 与 Python 环境写作约定

- nvm 在平台准备页内讲解，Windows 原生使用 nvm-windows，WSL/macOS/Linux 使用 nvm-sh；不把两者视为同一套命令。
- 说明 nvm 管理的是 Node.js 版本，npm 来自当前选择的 Node 安装。覆盖适用 LTS 的选择、node/npm 来源检查、切换后的全局 CLI、旧安装冲突与维护，不默认单独升级 npm。
- Python 环境在 P06 集中讲解：uv 为主线，Anaconda3/Conda 为完整独立分支。介绍解释器、项目 .venv、依赖、锁文件、工具环境、激活退出、复现与排障。
- Python/Node 是否必需取决于所选 Harness 安装方式；不要求用户为了使用独立二进制安装全部运行时。
- uv/Conda 示例使用独立读者练习目录，解释每个创建或安装命令的影响。本轮不在作者机器执行这些操作，也不让 uv 自动创建、同步或升级现有环境。
- 激活示例分别说明 Git Bash、PowerShell 7、WSL、macOS/Linux；验证解释器路径与版本，不通过系统 shim 继续任务，不复制 .venv 跨系统。
- AGENTS.md 模板使用可填写的环境要求，不复制作者个人目录、用户名或完整环境清单；根/子目录加载行为按客户端查证。

## 配置管理和 Herdr 约定

- CC Switch 先说明支持版本、受管客户端、实际写入对象和备份，再给添加、应用、验证与恢复流程；不默认九款 Harness 都被支持。
- 配置切换不能代替登录、订阅或额度授权，Windows GUI 与 WSL 的配置也不默认共享。教程用占位凭据，不展示真实密钥。
- Herdr 先讲普通终端布局，再讲 Agent 状态与协作。区分启动 Herdr 与在受管理 pane 中使用控制 CLI，不从管理环境外操作用户会话。
- Herdr 控制示例先检查 HERDR_ENV，使用当前版本帮助和返回的真实 ID；超时后先看状态，避免重复投递或自动回答审批。
- 多 Agent 演示是读者可选操作，不授权作者在本机启动 Agent、创建 pane 或发送任务。不自动关闭已有会话、停止服务器或连接远程机器。

## 事实核验与来源

以 [来源清单](03-official-sources.md) 为入口，写作时重新打开对应官方页面。必须核对项目、安装包发布者、支持平台、版本要求、命令、配置键、环境变量、快捷键、认证和升级方式。

状态用“待核验 / 官方文档已核验 / 本机实测 / 不适用”区分。官方没有说明不等于不支持，应写“官方资料未确认”。无可行受支持路线时提供 WSL 等受支持入口，不制造可复制但未经证实的安装命令。

官方文档链接放在相关段落和文末参考资料中；优先中文官方文档，必要时使用英文。网站正文采用普通 Markdown 链接，不能把对话中的特殊引用标记复制进去。

为每篇工具页记录：官方项目、版本或提交标识、文档核验日期、实际验证平台。未运行时写明“未执行安装与模型调用，仅核对官方资料”。价格、配额、可用模型不作为永久常量，说明核验日期并链接官方页面。

来源不可达时尝试同一官方项目的 README、文档目录或发行说明；仍无法证实时在维护记录中保留缺口。不得把未读取页面标为已核验，也不能把猜测写进命令速查表。

## 共用实践和示例

- 入门与九篇 Harness 教程都使用 `agent-lab` 文档任务；桌面应用依其实际界面选择工作空间，P07 定义共同任务和验收要求。
- 每篇工具需展示启动、任务输入、观察过程、审阅 diff 和完成判断；共用初始化步骤可链接 P07。
- 基础练习中的 Agent 不自动提交或推送。读者审查后需要提交时再明确演示。
- shell 命令、TUI 斜杠命令、键盘快捷键、自然语言提示词、输出分别展示，不能放在同一个可复制命令块里。
- 输出标为“示意输出”或“本机实测输出”。版本、用户名和会话 ID 用占位符，不能编造测试日志。
- API Key 使用 `<YOUR_API_KEY>` 等明显占位符，不把有效凭据、个人绝对路径或本机环境清单写入公开正文。
- 配置示例使用真实格式。JSON 不插入注释，只有官方接受 JSONC 时才使用 `jsonc`。
- 失败案例使用无效占位符、文档解释或读者可选练习，不为截取报错而触发付费调用。

## 页面结构模板

下面是工具页面的结构示意。用正式信息替换占位文字，删除不适用的可选功能；不能原样发布占位内容。

````markdown
---
title: 工具名
description: 本页帮助读者完成的具体任务
---

# 工具名

说明本页的学习结果，并链接环境准备和共用练习。

!!! info "版本与核验范围"

    - 对应版本：填写版本或提交标识。
    - 官方文档核验日期：YYYY-MM-DD。
    - 运行验证：填写实际范围；未运行时明确说明。

## 安装与验证

=== "Windows（Git Bash）"

    说明本段是在 Windows 原生 Git Bash 中操作。

    ```bash
    pwd
    printf '%s\n' "${HOME}"
    ```

    解释如何判断当前目录和用户目录。

=== "Windows（PowerShell 7）"

    仅在本节需要 PowerShell 路线时保留此标签。

    ```powershell
    $PSVersionTable.PSVersion
    Get-Location
    ```

    说明当前进程与执行位置，不混入 Bash 语法。

=== "WSL"

    在 WSL Linux 终端中操作，链接 WSL 环境准备。

=== "macOS"

    提供适用的官方安装路线和验证步骤。

=== "Linux"

    标明 Ubuntu LTS；给出适用的安装和验证步骤。

## 第一个任务

1. 进入练习目录。

    ```bash
    cd "<AGENT_LAB_PATH>"
    git status --short
    ```

2. 启动工具并输入任务。

    ```text
    阅读 README.md 和 notes/workflow.md，先说明修改计划。
    在 notes/workflow.md 中增加“完成标准”，包含三条可检查要求。
    完成后概述改动，等待我审阅。
    ```

3. 在工具外检查改动。

    ```bash
    git diff -- "notes/workflow.md"
    ```

??? question "看不到改动时如何检查"

    说明工作目录、任务执行状态与文件保存的检查步骤。

## 参考资料

- 在这里添加已核验的官方文档链接。
````

固定平台标签名称，利用项目已有的同名标签联动。Windows 两种 shell 分别使用“Windows（Git Bash）”与“Windows（PowerShell 7）”，不是同一标签的两种拼写。不适用的路线注明原因，不强求每款工具提供五套相同步骤。

## Zensical 语法约束

- Front matter 只使用现有配置支持的字段；每页仅一个 H1，H2/H3 表示正文层级。标题与导航中的显示名称保持一致。
- 内容标签、列表中的段落和代码块、admonition 均缩进四个空格。折叠提示使用 `???`，不用未启用的 GitHub callout。
- 代码围栏使用真实语言，如 `bash`、`powershell`、`toml`、`json`、`text`；输出块使用 `text` 并禁用复制按钮时采用项目支持的属性语法。
- 相对链接指向 `.md` 源文件；正文不链接 `site/`、生成 HTML 或本机绝对路径。
- 提示优先用 `!!! note`、`!!! tip`、`!!! warning`；警告只用于具体风险，例如覆盖凭据或清除会话。
- 不使用尚未启用的 snippets、GitHub callouts、caption、directives 或 tablesort。长表格优先拆分或改写为分节。
- Mermaid 仅用于解释 Agent 循环、学习路线、API 链路与协议转换等确有帮助的结构，采用现有 `mermaid` 围栏，不引入新脚本。
- 新增资源按任务要求选择本地或图床存储；图床图片只使用上传返回且经公开访问检查的 URL。已处理图片的来源、哈希、正文引用、图床地址和本地留存状态分别记录在图片清单中。
- 不同页面不能共用 `README.md` 与 `index.md` 作为同目录入口；栏目入口固定为 `index.md`。
- 数学公式遵守根目录 `AGENTS.md`：块级用 `$$`，多行优先 `align*`，禁止局部换行间距和自动编号。

## 作者执行边界

编辑使用 `apply_patch`，搜索优先 `rg`，命令只用 Git Bash。遵守工作区现有改动，不覆盖用户内容。不自行安装依赖、创建或升级环境，不自动提交、推送或部署。

正文验收阶段可以按完整任务约定使用现有环境构建站点。若需要 Python，先按全局规则激活并确认解释器；本项目要求 Python 3.14，默认 base 的旧版本不自动满足要求。使用已有项目环境前也要确认来源，不让 `uv run` 隐式创建环境或下载解释器。

## API 协议专题约定

- 区分模型、提供商、客户端格式与上游格式，不能因域名或“OpenAI 兼容”标签推断实际协议。
- 当前 Codex 使用 `wire_api = "responses"`；Chat 上游通过经核实的转换路径使用，不写成 Codex 原生仍接受 chat。
- DeepSeek 原生 Responses 和 Anthropic 兼容接入优先；Chat 路由作为可选练习。明确旧截图的版本和适用范围。
- 区分普通聊天成功、工具调用成功和整个项目任务验收；本站未执行真实 API 请求时不能伪装为已实测。
